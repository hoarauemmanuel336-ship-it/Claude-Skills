OBJECTIVE

Produce a complete study path on the requested subject, delivered as a standalone HTML file that the reader opens in a browser, on a computer as well as on a phone. The path leads from the very first notion to mastery of the subject. In it, the reader follows their progress topic by topic and copies, with a single tap, whatever they want to study, in order to ask the AI for the book, the diagram or the article that will teach it to them.

The reader learns with the AI, through the books, diagrams and articles it composes for them. Each topic of the path is therefore material to be written up in one of these forms, and each point to learn lends itself to becoming a chapter, a section of a diagram or a part of an article.

CONTENT

Architecture. The path is built on three levels. Blocks are the major parts of the subject; each one carries a color. Themes are the collapsible sections of a block, numbered from 01 to the end of the path. Topics are the cards of a theme: each one is a unit of study. The AI first draws the full map of the subject, then divides it along its natural joints: the number of blocks, themes and topics follows what the subject calls for.

Order. Themes follow one another in the order in which one learns best: the foundations first, which give the vocabulary and the sources, then the heart of the subject, then its extensions, and finally the synthesis, which ties everything together and teaches how to pass it on. Within a theme, each topic builds on those that precede it. The path presents itself as a plan organized by major themes, in one continuous order.

Topic. Each topic carries a short noun-phrase title, a one-line description that says in plain words what it is about, and a list of points to learn, as many as the material calls for. Each point names a precise notion, a distinction, a work, a text or a figure, so that on its own it forms one part of the book, the diagram or the article the reader will ask for. The points are written for a novice discovering the subject, naming the exact terms they will learn to master.

Explanations. The banner carries an explanation in three short paragraphs: what the path covers and how each topic is copied to be requested from the AI as a book, a diagram or an article; how the themes follow one another and how to mark each topic; then how progress is kept: on its own in the browser when the browser allows it, and in the file itself through the Save button, which downloads the updated path, to be opened next time in place of the old one. Each block with several themes carries an explanation that sets out its overall logic: what it gathers, why in this order, what it prepares. Each theme carries an explanation of one or two sentences that says what is learned there and why it comes at this place. Bold marks the two or three key notions of each explanation.

Typography. All visible text goes through a typo() function, applied at render time, which composes English typography: curly apostrophe ’ in place of the straight apostrophe, curly double quotes “ ” with single quotes ‘ ’ inside them, no space before : ; ! ?. The data is written with straight apostrophes and straight quotes, and the function composes them. Commas, parentheses and colons carry parenthetical asides.

WRITING WITH SEVERAL HANDS

Blocks can be entrusted to subagents who write in parallel, each one the themes, topics and points of one or more blocks. The main AI then keeps charge of the unity of the path, from the banner to the last topic.

A shared brief comes before the writing. The main AI writes it in a file that each subagent reads in full before writing. In it, it sets down the full map of the subject, the division into blocks and themes with their numbering, each subagent's share, the audience, the tone, the rules of substance and form, the shape of the data and of the topic keys, and the form in which each share is delivered.

A single-handed review follows the writing. Before assembly, the main AI itself reads the entire path, from the first theme to the last, in the reader's order. It gives all the texts one voice. It tunes each theme to those that precede it, so that the continuous order of the path carries through from one block to the next. It places each notion, each work and each figure in the topic where it is learned best, and rewrites the points that repeat what another topic already carries, replacing them with fresh material. It then composes the explanations of the banner and of the blocks itself, on the reviewed path. The path then reads as the plan of a single author, and each topic keeps its full substance.

ANIMATIONS

Principle. An opening reads as an unfolding, a closing as a packing away; entrances are slower than exits, and every cascade completes in under one second. Animations go through the Web Animations interface, element.animate().

Theme height. The content wrapper is a one-row grid: grid-template-rows 0fr collapsed, 1fr open, transition .4s cubic-bezier(.2,.7,.3,1) on opening, .3s cubic-bezier(.4,0,1,1) on collapsing. Its only child carries min-height:0, overflow:hidden and visibility:hidden at rest. Two classes carry the state: the expansion class sets the 1fr, the chevron's rotation and the arrow's state, and toggles on click in both directions; the opening class carries the sticky position and the visible separator, added on the opening click and removed at the actual end of the collapse. The JavaScript sets visibility:visible and overflow:hidden at the first instant of any movement, releases the overflow at the end of the opening, to let the halos breathe, and sets visibility:hidden again at the end of the collapse.

Opening cascade. Separator at 0ms, rail line at 80ms, fill line 40ms later, theme copy button 40ms later, then each card 40ms after the previous one. Each element enters with opacity 0 → 1 and translateY(8px) → 0, over 450ms in cubic-bezier(.2,.7,.3,1), fill both. The last start falls at 600ms at the latest: beyond that, all intervals shrink in the same proportion, with a floor of 12ms.

Closing cascade. The same elements leave in reverse order, from the last card to the separator, with opacity 1 → 0 and translateY(0) → translateY(-6px), over 250ms in cubic-bezier(.4,0,1,1), with 15ms between two starts and a last start capped at 150ms, while the height collapses.

End and lock. The actual end of a movement is the joint promise of all its animations and of the height transition, with a 700ms safety net. At that end, the animations are cancelled with cancel(), which returns each element to its base style, and the progress rail is recomputed. Each theme carries a lock: a new click during a movement first cancels the animations, the listener and the pending timeout on that theme, then starts the new movement; a movement token discards stale endings.

The reader's place. When a theme collapses while its header is pinned at the top of the screen, the page first settles, through an immediate scrollTo, on the top of the theme; the closing then plays, and the header stays where the reader touched it.

Global cascade. On opening through the arrow, the closed themes open from first to last, 120ms between two starts, last start capped at 1000ms. On closing, the open themes close from last to first, 60ms between two starts, last start capped at 500ms. The first one concerned starts immediately. Each timeout is recorded in a registry that is cleared on every click of the arrow.

Unfolding explanations. The banner, the block heading, the theme + and the topic card unfold their content through the same grid wrapper. The unfolded content keeps its clicks, text and copy buttons included, and folding is controlled from the element that unfolded it. The wrapper: 0fr → 1fr in .35s cubic-bezier(.2,.7,.3,1), back in .25s cubic-bezier(.4,0,1,1); the child carries min-height:0, overflow:hidden, and visibility:hidden with a .25s delay on folding, visible immediately on unfolding. On unfolding, the content enters with opacity 0 → 1 and translateY(6px) → 0 over 350ms; on folding, it leaves with opacity 1 → 0 over 200ms in cubic-bezier(.4,0,1,1), fill forwards, the animation being cancelled on the next unfolding.

Pulse. When a topic becomes done, its dot grows to 1.45 at one third of the animation then returns to 1, while a ring in the block's color at .7 widens from 4px to 16px as it fades, over 650ms in cubic-bezier(.2,.7,.3,1).

Reduced motion. Under prefers-reduced-motion, read through matchMedia, durations drop to 0.01ms, delays to 0, and the fade and the pulse stay at rest.

SAVED PROGRESS

Three keepers. The path entrusts its progress to three keepers and serves them at every gesture: the file itself, which carries the written progress, kept up to date by the host page or by the save button; the browser's local storage, when the path is opened directly, as a file or as a page, under a key specific to the path, derived from its subject; the host page, when the path is placed in a sandboxed frame, where local storage belongs to the page and the frame addresses it by message. Writes are made inside a try, and the path carries on with whatever it obtains.

Written progress. The file carries in its head, just before the closing of head, a block reserved for progress: `<script type="application/json" id="lv-progression">`, which contains a JSON object {"maj": time of the last change in milliseconds, "sujets": {topic key: status}}. The statuses are written there as en-cours, termine and a-revoir; a to-do topic is absent from the block. A new path carries the block with maj at 0 and sujets empty. This block is the part of the file that the host page and the save button rewrite: the file the reader retrieves thus carries all of their progress.

State. The state gathers the status of each topic; the time of the last change of a topic's status, under the name maj; the list of open themes, that is, of the themes carrying the expansion class, the one that says from the moment of the click which direction the reader intends; the list of unfolded explanations, banner, block headings, themes and topics, each designated by a stable key; and finally the size step. Each topic has a stable key, made of letters from a to z, uppercase included, digits, dots, hyphens or underscores, 80 characters at most, written once in the data, which keeps its status when the plan is reorganized: this is the form that the host page and the save button write into the file.

Sending. The state is recomposed from the document and sent to local storage and to the host page at every gesture: a change of a topic's status, the opening or collapsing of a theme, the arrow's cascade, the unfolding of an explanation, a change of size step. It is also sent when the page is hidden or left, on visibilitychange to the hidden state and on pagehide. Toward the host page, the sending is written parent.postMessage({lvEtat:etat},'*'), and it takes place when the path is actually placed inside a frame, which the comparison parent!==window establishes. At each change of a topic's status, the path also sends, under the same condition, parent.postMessage({lvProgression:{maj:maj,sujets:sujets}},'*'), in the exact form of the block: the host page writes it into the file. Opened directly, the path updates the save button's dot at each change of a topic's status: it lights up when maj differs from that of the progress written in the copy of the file.

Resuming. At the first instant of the script, the path reads the written block and local storage: the topic statuses come from the more recent of the two according to maj, the rest of the state comes from local storage, and the path builds itself from it. It then asks the host page for its state with parent.postMessage({lvEtatVoulu:1},'*'), under the same condition. The page replies with a message {lvEtat:etat}, and it may repeat it several times during setup. The path accepts the messages whose source is its parent and applies the received state on each arrival, until the reader's first gesture, which opens their own reading. There again, the topic statuses come from the more recent, according to maj, of the received state and the written progress; the rest comes from the received state. The received state is applied all at once: a class on the root element suspends all transitions, the retained themes appear in their open state at rest, the retained explanations unfolded, the topics in their status, the bars at their level; the arrow falls into step, the class is removed two frames later and the rail is recomputed. The page thus built then receives the reading position, which the host page keeps and restores itself. When the progress thus resumed differs from that of the block, the path sends lvProgression once, and the file falls into step with it; opened directly, it lights the save button's dot.

Updated file. The script stands as the last element of body. Its first act, before any construction of the page, is to keep a copy of the path's source: the declaration <!DOCTYPE html>, a line break, then document.documentElement.outerHTML, which at that instant carries the whole document as it was delivered. The SAVE button composes the updated file from this copy: it replaces the contents of the progress block with the present progress, {maj, sujets}, written by JSON.stringify, in which every opening angle bracket takes its JSON-escaped form, a backslash followed by u003c, so that the block remains a simple data block. It turns it into a Blob of type text/html;charset=utf-8 and downloads it through a temporary link carrying the download attribute, added to the document, clicked, then removed; the object URL is released one second later through URL.revokeObjectURL. The downloaded file takes the name of the opened file, drawn from the last part of location.pathname, decoded, when it ends in .html, and otherwise the path's name drawn from its subject. The kept copy in turn receives the written progress, and the button's dot goes out. The reader then opens this file in place of the old one; on a phone, the browser stores it in its downloads or in the Files app. When it is opened, resuming reads the block and recovers all the progress, in any browser.

UPDATING A STUDY PATH

When the reader hands over an existing path to have it evolve, the AI carries over its progress block as it is and keeps the key of each retained topic, even when renamed or moved; a new topic receives a new key. It reads the block to learn how far the reader has come and evolves the path accordingly: what they have done keeps its place, what they have marked to review can be deepened, and what follows builds on what they already know. A path composed before the save button existed receives it at each update, along with the sentence that presents it in the banner's explanation and the script placed as the last element of body.

DELIVERY

The path is delivered as a single HTML file, with CSS and JavaScript inline; with lang="en" and the viewport tag width=device-width, initial-scale=1. The path's data, blocks, themes, topics and explanations, is held in arrays at the head of the script, and the page is built from them. The script is the last element of body. The file name takes up the subject of the path.
